# 2026-09-10

## 用户名改为按内网 IP 主机号自动派生

需求：192.168.5.102 → 主机号 102 → 用户名 ID102。

用户确认的两个选择：
1. **自动预填，仍可改**（不是强制）——登录页预填派生名，可手动改，进房间后点自己名字也能改
2. **重名自动加序号**——第二个 .102 显示 ID102-2

实现：
- 新增 `server/identity.js`：`hostNumber(ip)`（IPv4 取最后一段；IPv6 取最后一段 16→10 进制；兼容 `::ffff:` 与 `%zone`）、`deriveName(ip, taken)`（冲突追加 -2/-3）、`isAutoName(name)`（`/^ID\d+(-\d+)?$/`）
- 命名在**服务端**完成，前端改不了；`/api/me` 未登录时返回 `ip` + `suggestedName`，前端预填
- `POST /api/login` 的 `name` 留空即自动派生
- `syncAutoName()`：名字仍是自动格式的用户，IP 变了会跟随更新；手动改过名字的（不匹配自动格式）永不覆盖
- 冲突判断只看**当前在线**用户（`online` map），前一个人下线后来者会收回 ID102

踩坑（重要）：
- **Socket.IO 的 `handshake.address` 不认 X-Forwarded-For**，反代后面会拿到代理自己的 IP，导致所有人被改名成同一个。改用 `proxy-addr` 手动按同一套规则解析，HTTP 与 WS 统一走 `clientIp(req)`。
- Express 会自己把 `"loopback,linklocal,uniquelocal"` 按逗号拆开再传给 proxy-addr，但直接调 `proxyAddr(req, str)` 不会拆——要自己 split 成数组。`true` 要映射成 `() => true`。
- `trust proxy` 默认设为 `loopback,linklocal,uniquelocal`（只信本机/内网代理），防止局域网内伪造 XFF 冒用身份；公网反代场景需 `TRUST_PROXY=true`。

验证：冒烟测试扩到 **24 项全过**。用 `X-Forwarded-For` 模拟不同内网 IP 来测多用户，测试里 `req()`/`connect()` 都支持独立 cookie jar 与自定义 header。新增用例：派生名、空名字登录、同 IP 冲突加序号、手动名不被覆盖、Socket 连接不改写自动名/手动名。

前端改动：`public/index.html` 加 `#ipHint` 提示"检测到内网地址 x.x.x.x，已自动生成用户名"；`app.js` 的 `bootstrap()` 预填 `suggestedName`，登录不再强制非空，改名框留空可恢复自动名。

新增依赖 `proxy-addr`；新增环境变量 `NAME_PREFIX`（默认 ID）、`TRUST_PROXY`。
