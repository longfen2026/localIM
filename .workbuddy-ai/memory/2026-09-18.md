# 2026-09-18

## 修复：发送图片报"图片已失效，请重新上传"，随后消息消失

现象：前端选图发送 → toast「图片已失效，请重新上传」→ 4 秒后那条待发消息被移除。

排查（server/index.js:455 是唯一抛出该文案的地方）：

```js
const info = store.takePendingUpload(String(p.fileId), user.id);
if (!info) return done('图片已失效，请重新上传');
```

`takePendingUpload` 只认上传时登记的 fileId 字符串；查不到就报"已失效"。写临时脚本复现（起服务 → 登录 → 上传 1x1 PNG → 用两种 payload 发 `msg:send`）：

- payload.fileId = `{fileId:'…', kind:'image'}`（对象）→ `String()` = `[object Object]` → 「图片已失效」
- payload.fileId = `'…'`（字符串）→ `{ok:true, type:'image'}`

根因在**前端 `public/app.js` 的 `sendImageFile`**：

```js
uploadImage(file, cb).then((fileId) => doSend({ fileId, kind: 'image' }, …));
```

而 `uploadFormData` 兑现的是**整个上传响应**（`resolve(data)`，即 `{fileId, kind}`），不是 fileId 字符串。于是 socket 里发出去的是对象，服务端 `String(obj)` → `[object Object]` → 必然查不到 → 误报"已失效"；失败分支里的 `setTimeout(removePending, 4000)` 让消息 4 秒后消失。

对比 `sendChatFile` 写的是 `data.fileId`，是对的——所以**只有图片路径有此 bug，文件发送正常**，冒烟测试也测不到（它直接用 `upBody.fileId` 发 socket，绕过了前端这段）。

改动：
- `public/app.js`：`.then((fileId) => doSend({ fileId, … }))` → `.then((data) => doSend({ fileId: data.fileId, … }))`
- `server/index.js`：`msg:send` 里统一 `const fileId = typeof p.fileId === 'string' ? p.fileId.trim() : ''`，非字符串直接返回「参数错误：fileId 无效」；图片/文件两个分支都改用该变量，不再 `String(p.fileId)`
- `scripts/smoke-test.js`：新增回归用例「fileId 非字符串返回明确的参数错误」

验证：`npm test` **54/54 通过**（原 53 项 + 新增 1 项）。

## 教训

前端 upload 回调一律 `data.fileId`，别把响应对象当 id 用；服务端对外部入参做类型归一化，否则错误提示会把"参数错了"误导成"资源过期了"。
