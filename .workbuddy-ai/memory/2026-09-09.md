# 2026-09-09

## 从零搭建 localIM 局域网聊天室

需求：局域网文字+图片聊天室，免密登录（只输主机名），Cookie 保持登录态，服务端长期保存历史，Docker 部署 + 数据卷持久化。

技术选型（无构建步骤，零编译）：
- 后端：Express 4 + Socket.IO 4 + cookie-parser + multer 2（不用 1.x，有漏洞告警）
- 前端：原生 HTML/CSS/JS，Socket.IO 客户端直接用服务端自带的 `/socket.io/socket.io.js`，避免 CDN 依赖（局域网可能无外网）
- 持久化：消息用 append-only 的 `messages.jsonl`（每行一条，启动时载入内存）+ `users.json`（防抖写回，tmp+rename 原子替换）+ `uploads/YYYYMM/` 存图片原文件 + `.cookie-secret`（保留则重启后登录态不失效）
- 鉴权：签名 Cookie（`s:` 前缀 + cookie-signature），Socket.IO 握手时手解析 cookie 校验，失败返回 UNAUTHORIZED
- 图片宽高：只解析文件头（PNG/JPEG/GIF/WEBP），不引入 sharp 之类的原生依赖，保证 alpine 镜像能直接跑

关键文件：server/{index.js,store.js,media.js,config.js}、public/{index.html,style.css,app.js}、Dockerfile、docker-compose.yml（./data:/app/data）、scripts/smoke-test.js

验证：`npm test` 冒烟测试 18 项全通过（登录/自动登录/文字/图片/类型白名单 415/历史分页/落盘/重连恢复/登出）。服务已在 3000 端口后台运行（task 0QyL7z）。

约定：
- 数据目录统一由 `DATA_DIR` 环境变量控制，本地默认 `<项目根>/data`，容器内 `/app/data`
- 前端渲染一律用 createElement + textContent，禁止 innerHTML 渲染用户输入
- 图片先 POST /api/upload 拿 fileId 再走 WebSocket 发消息；30 分钟未发出的孤儿文件由服务端 GC

## 追加：GHCR 发布 CI

新增 `.github/workflows/docker-publish.yml`，两个 job：
- `test`：ubuntu-latest + setup-node 22 + `npm ci` + `npm test`，作为打包前门禁
- `build-push`：checkout → 镜像名转小写 → QEMU → Buildx → 登录 GHCR（用内置 `GITHUB_TOKEN`，需 `packages: write`）→ metadata-action 打标签 → build-push-action

策略：PR 只构建 amd64 不推送；push 主分支/tag 构建 amd64+arm64 并推 `latest`、分支名、`v1.2.3`、`1.2`；workflow_dispatch 可指定平台与是否推送。缓存用 `type=gha`。

踩坑记录（重要）：
- GHA 表达式里**不要直接用 `inputs.xxx`**，push/tag 事件下该 context 不存在会报错；用 `github.event.inputs.xxx`（非 dispatch 时为 null，取属性返回 null 不报错）
- GHCR 镜像名必须全小写，用 `tr '[:upper:]' '[:lower:]'` 处理 `${GITHUB_REPOSITORY}`

同步改动：
- Dockerfile：去掉 `shadow` 依赖与 `getent`（busybox 可能没有），改用 `awk` 查 /etc/group、/etc/passwd 判断 uid/gid 是否已存在；`npm install` 改 `npm ci`；HEALTHCHECK 内联 JS 改用单引号避免转义地狱
- .dockerignore 补 `.github`、`scripts`，避免被打进镜像
- README 新增「用 GHCR 镜像部署」与「自动发布」两节

本机没有 docker（`docker: command not found`），镜像构建未实测，只做了 YAML 校验与 shell 片段模拟。

## 镜像瘦身 166MB → ~55MB

先量化再动手（查 registry manifest 的 blob 尾部 4 字节 ISIZE 可拿到解压后大小，不用真拉镜像）：
- `node:22-alpine` amd64 解压后 **159.5 MB**（4 层：alpine 8.3 + node 层 146.1 + 5.1 + 0）
- 我们自己的代码 + 生产依赖只占 ~7 MB → 瘦身必须从基础镜像下手

关键认知：**在 Dockerfile 里 `rm -rf` 基础镜像自带的文件不会减小镜像体积**（overlayfs 只加 whiteout，底层数据仍在）。必须换基础镜像或用多阶段复制，让文件根本不进最终镜像。

采用方案：多阶段。构建阶段 `node:22-alpine` 跑 `npm ci`；运行阶段 `alpine:3.22` + `apk add nodejs icu-data-full tzdata ca-certificates`。
- Alpine 官方 nodejs 包 22.23.2 仅 **18.5 MB**（x86_64）/ 17.8 MB（aarch64），因为不带 npm/corepack/头文件
- 依赖清理：`rm -rf @types` + shell 通配删 docs/examples + `find -type f \( -name '*.md' -o '*.map' -o '*.d.ts' ... \) -delete`，**实测 11MB → 5MB，冒烟测试 18/18 仍通过**（已验证精简后依赖能正常加载并跑完整流程）
- 不用 `find -prune`（busybox find 支持情况不确定），改用 shell 通配避免构建失败
- icu-data-full(11.8MB) + tzdata(0.2MB) 是为中文和 Asia/Shanghai 时区；换 icu-data-en 并去掉 tzdata 可再省 12MB

原 Dockerfile 另存为 `Dockerfile.full` 作回退（.dockerignore 已排除）。README 新增「镜像体积」章节说明 docker images 显示解压后、registry 显示压缩后，两者差 2~3 倍。

仍未实测：alpine+apk nodejs 的运行时（本机无 docker）。用户需自行 `docker build` 验证。
